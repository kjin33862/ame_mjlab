# 발 디딤 δ=0.30 + AlphaNIST + 균등 섞기 0.2 과제 준비 보고 (학습 안 함, 여기서 멈춤)

## 결론 (2차: 균등 섞기 추가 후)

1. **균등 섞기 0.2로 징검다리 레벨 3·4가 각각 2.0%씩 뽑힌다** (섞기 없는 AlphaNIST 0.01%, SGS 0.04%). 레벨 3 이상 합계는
   2000 iteration 이후 **14.1%**다(섞기 없는 AlphaNIST 0.1%). 레벨 2는 p_2 = 0인 2000–3999 구간에도 **2.0%**(섞기 없으면 0.01%)이고,
   후반에는 14.0–22.0%다. 섞기 없는 AlphaNIST의 15–25%에서 ×0.8만큼 줄어든다. 레벨 2 이상 합계는 16–36%다.
2. 정책은 바뀌지 않았다: 섞기는 `(1 − m) × 커리큘럼 분포 + m / L`이고, m은 설정 값이다(코드 이름 `uniform_mix`, 아래 참고).
   기본값 0이고, 새 과제만 0.2다. 기존 28개 과제의 학습·play·rl 설정 repr 해시는 변경 전과 같고, 테스트 110개 통과·1개 skip이다
   (skip은 onnxruntime 미설치로 생긴 기존 skip).
3. **실제 env에서 확인:** 새 과제로 64 env × 3 iteration 학습은 정상 종료됐다. 다만 3 iteration 안에는 끝난 에피소드가 없어
   p_k가 모두 0이고, 그 경우 prob_k는 섞기 유무와 관계없이 10%(균등)라 섞기를 구별할 수 없었다. 그래서 실제 과제 설정으로
   env 64개를 만들고, 발 디딤 run 마지막 구간의 p_k를 그 커리큘럼 항목의 버퍼에 넣은 뒤, TensorBoard로 가는 prob_k를 읽었다.
   그 결과 세 지형 모두 0.8 × AlphaNIST(p) + 0.02와 1e-7 이내로 일치했고, p = 0 레벨은 2.0%였다(아래 표).
4. 비용: 균등 몫은 지형 종류별로 레벨마다 2%라서 징검다리에서는 p = 0인 레벨 3–9(틈 15–45 cm)에 표본의 14%가 간다.
   그중 레벨 5–9(25–45 cm)는 지금 정책에는 사실상 불가능한 레벨이라, 그 몫은 실패 표본이 될 가능성이 높다.
   쉬운 레벨(징검다리 L0–1, 계단 L0–4)은 섞기 없는 AlphaNIST 대비 약 ×0.8로 줄어든다.
5. 예측의 한계(1차와 같음): 이 표는 SGS run의 p_k를 넣은 정적 계산이다. 섞기가 있으면 레벨 3 이상 버퍼가 계속 갱신되므로,
   학습 중 p_3이 0에서 벗어나면 AlphaNIST 가중치가 그 레벨로 붙는다. 그 효과는 표에 들어 있지 않다.

### 이름: 요청의 "eps" → 코드에서는 `uniform_mix`

SGS 파라미터에 이미 `eps`(= 1e-8, 가중치의 바닥값)가 있다. 그래서 섞기 비율 키는 `uniform_mix`(상수 `UNIFORM_MIX_KEY`)로 했다.
`SGS_PARAMS`/`ALPHANIST_SGS_PARAMS`에 키를 넣지 않고, 없으면 0으로 읽는다. 키를 넣으면 기존 SGS 과제의 설정 repr이 바뀌기 때문이다.
m = 0이면 `sgs_probs`는 기존 softmax를 그대로 반환하고, 테스트가 비트 단위로 같음을 확인한다.

# 1차 보고 (균등 섞기 추가 전, 기록용)

아래의 "설정 차이는 δ와 t·κ·T뿐"과 2080 Ti 명령 이전 내용은 1차 시점의 상태다. 현재 diff는 위 2차 섹션 참고.
2080 Ti 명령은 그대로 유효하다(과제 이름 동일).


## 결론

1. **AlphaNIST로 바꾸면 징검다리 레벨 2는 많이 뽑히지만, 레벨 3·4는 사실상 0이다.** 발 디딤 run의 p_k를 넣으면
   레벨 2 비율은 SGS 0.4–4.0% → AlphaNIST **9.9–25.0%** (4000 iteration 이후). 그러나 **레벨 3·4는 각각 약 0.01%로,
   SGS(약 0.04%)보다도 낮다.** "레벨 2 이상" 합계는 4000 이후 10–25%로 5%를 넘지만 **전부 레벨 2 몫이고, 레벨 3 이상은
   모든 구간에서 5%보다 훨씬 작은 0.1% 미만**(1000 iteration 이후)이다. 2000–3999 구간은 p_2도 0이라 AlphaNIST의 레벨 2 이상
   합계가 **0.08–0.09%(5% 미만)**다.
2. 이유: 두 방식 모두 p = 0인 레벨의 가중치가 바닥값(AlphaNIST √eps = 1e-4, SGS는 eps 바닥)으로 떨어진다. 징검다리 레벨 3–9의 버퍼는
   첫 1000 iteration에 실패 100개로 채워졌고(fill_min = 100), 뽑혀야만 갱신되므로 계속 p = 0에 갇힌다. AlphaNIST는 SGS의
   온도 T = 2(로짓을 반으로 줄여 바닥 레벨을 덜 죽임)가 없어서 p = 0 레벨을 오히려 더 강하게 배제한다.
3. 따라서 이 과제가 개선하는 것은 "레벨 2(틈 10 cm) 노출 약 6배"이고, "레벨 3·4(15·20 cm) 노출"은 **학습 중 p_2가 올라가
   p_3이 0에서 벗어나지 않는 한 기대할 수 없다.** 레벨 3·4 노출이 목표라면 커리큘럼 쪽에 별도 장치(예: 균등분포 혼합 하한,
   미방문/오래된 버퍼의 낙관적 p)가 필요하다 — 이번 과제에는 넣지 않았다.
4. 계단: AlphaNIST는 쉬운 레벨(p ≈ 0.7–0.8)에서 질량을 덜어 경계 레벨로 옮긴다. 예) 올라가기 9000–9999: L5 10.7→14.1%,
   L6 8.3→13.3%; 내려가기 4000–4999: L8 0.1→3.7%, L9 0.0→1.7%.
5. 코드: 새 과제 `Ame-Mjlab-Gap-Edge-AlphaNIST-AngW4Z-Contact-FootholdD30-Velocity-Rough-G1` 등록. 기존 발 디딤 과제와의
   설정 차이는 **δ(train·play)와 SGS 파라미터 t·κ·T(train)뿐**이고(rl 설정 차이 0줄), 기존 28개 과제의 env/play/rl 설정
   해시는 변경 전후 동일. 테스트 43개 통과. 64 env × 3 iteration 스모크에서 징검다리·계단 상/하 모두 `p_0..9`, `prob_0..9`가
   TensorBoard에 기록됨을 확인(스모크 로그는 삭제).

**주의(예측의 한계):** AlphaNIST 열은 "SGS run에서 관측된 p_k를 AlphaNIST 식에 넣은 값"이다. 실제로는 샘플 분포가 바뀌면 정책과
p_k도 바뀌고(되먹임), δ = 0.30으로 보상도 바뀌므로 수치는 출발점 추정이다. SGS 열은 로그된 prob_k와 모든 구간에서 0.1%p 이내로
일치해 계산 자체는 검증됨.

## 단계 1: AlphaNIST 구현과 파라미터
